# OpenStax Errata Review — 2026 (first run)

Prepared: 2026-08-01, by the scheduled `openstax-errata-yearly-review` task.
This is a **report only** — no section HTML was edited and nothing was committed.
All recommendations below require Math Department sign-off before any local edit lands
(per CLAUDE.md's fidelity/departure policy).

No prior snapshot existed in `errata-reports/`, so this is a baseline run: every item
below is "new." Next year's run will diff against `errata-reports/2026-snapshot.json`
and only surface items that are new or changed since this baseline.

**Build-timing correction (added after Mike's review):** `tools/build-section.mjs`
fetches each section's CNXML live from GitHub at the moment it's run — it's not a
point-in-time copy. Since every section file currently live on this site was first
built between **2026-07-07 and 2026-07-19** (checked via `git log --follow` per file),
any OpenStax erratum with `resolution: Approved` and a `corrected_date` *before* that
page's own build date was already baked into the content when the page was built —
there's nothing to mirror. This matters a lot: the vast majority of "Approved" fixes
below have `corrected_date` in Feb–June 2026, well before any of this project's builds.
Only items whose `corrected_date` falls on or within ~1–2 days of the specific page's
build date are genuinely ambiguous (OpenStax's CMS date may lag or lead the actual
content push) and worth a quick manual check; a handful were spot-checked directly
against the live HTML and are called out as confirmed either way. Every table below has
been corrected for this — "Already incorporated" now means *no action needed*, not
"mirror this."

Reading this table: **"Already incorporated" needs zero action** — these are Approved-and-
corrected OpenStax fixes whose `corrected_date` predates this project's build of that page,
so the fix is already in our content (this includes one item, Calc V3 #29010, whose
`corrected_date` was same-day as our build — spot-checked directly against the live HTML
and confirmed the correct value is already there). **"Confirmed/likely still open"** is only
the 2 items I directly verified against the live page text and found the erratum's issue
genuinely still present (Calc V1 #28780, Calc V3 #29037) — real, ready-to-action items.
**"Unconfirmed by OpenStax yet"** covers two different things lumped together: `Editorial
Review` items with no OpenStax resolution at all, and 13 `Approved` items whose
`corrected_date` falls within 0–2 days of the page's build date that I did **not**
individually spot-check (time-boxed this run) — worth a quick manual check before next
year's automated pass if you want to get ahead of them. **"Declined"** means OpenStax itself
said no action (Not An Error, Duplicate, Major Book Revision, or inconclusive) — nothing
needed from us regardless of build timing.

This is a first-run baseline (no prior snapshot in `errata-reports/`), so every item counts
as "new" this year; next year's run diffs against `errata-reports/2026-snapshot.json`.

"Actionable" = the erratum's location resolves to a specific section this project has
marked `ready: true`. "Chapter-level" = the erratum's OpenStax location field only names
a chapter (or "Answer Key: Chapter N" / "Chapter Review"), not a section — the chapter
itself is live, but pinning down which page needs the fix requires opening the erratum
on openstax.org and reading the exercise number cited. "Roadmap-only" = the chapter/book
isn't built yet; these are listed only as a one-line heads-up per CLAUDE.md's instructions,
not itemized.

A recurring theme worth flagging up front: **figure-only errata need no local action.**
Per CLAUDE.md convention 6, most figures are hotlinked directly from OpenStax's own GitHub
repo (`<img>` pointing at their asset, not a local copy). If OpenStax corrects an image
(wrong arrow direction, wrong color, mislabeled axis), our page picks up the fix automatically
once it's merged upstream — no edit needed here unless the filename/path changes. Two items
below (Precalc #29769, Calc V3 #28901/#29001) are flagged this way explicitly.

## Notes on process / gotchas hit this run

- The OpenStax errata `location` field is inconsistent: most items include "Section N.M,"
  but a meaningful minority give only a chapter name, a bare "Chapter N.M" without the word
  "Section," an "Answer Key: Chapter N" line, or a chapter-review reference with no section
  at all. 23 items across all books needed this kind of manual disambiguation via detail text.
- A handful of records have an internally contradictory-looking `resolution`/`resolution_notes`
  pairing (e.g. resolution says "Not An Error" but notes say "addressed in another report and
  will be included in the next print cycle"). Flagged inline each time it came up rather than
  silently picking one field to trust.
- CLAUDE.md and README.md both described this project as much smaller than it actually was at
  the time of this run (README still framed it as just Section 6.1; CLAUDE.md's own prose still
  said "6.1–6.2 complete"). The actual BOOK manifest covered 5 books, ~294 sections, most of
  them `ready: true`. Both docs were refreshed in a follow-up pass the same day (see git log) —
  next year's run should re-check this drift hasn't crept back in before trusting doc prose.
- **Build-timing matters and was missed in the first draft of this report.** `tools/build-
  section.mjs` fetches CNXML live at build time, not a fixed historical snapshot, so any
  OpenStax `corrected_date` before a page's own build date is already baked in — nothing to
  mirror. Get each live page's actual first-build date via
  `git log --follow --diff-filter=A --format=%ad --date=short -- <path>` (note: use `--follow`,
  not a bulk `--diff-filter=A --name-only` over all files at once — files that predate a
  directory reorganization, like this project's original flat `sections/*.html` layout before
  the multi-book refactor, show their bulk "first added" date at the *old* path, not the current
  one, and silently vanish from a naive path-keyed lookup). Compare that build date against each
  erratum's `corrected_date` before recommending any fix be mirrored. Also double-check the
  "chapter is live" determination isn't fooled by a chapter where *zero* sections are actually
  `ready: true` — that bug slipped into this run's first draft for Calculus Volume 1's Chapter 1
  and was only caught during the build-timing pass; it's now fixed in this file's Calculus
  Volume 1 section.
